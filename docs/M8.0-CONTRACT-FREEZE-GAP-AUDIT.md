## 1. Architectural invariant: AccessZone is producer intent and end-to-end lineage

AccessZone is assigned at file/job submission by the trusted Spring Boot/business boundary. It is not discovered by OCR, parsing, splitting, M7 replay, or the M8 transport adapter.

Required lineage:

```text
Spring Boot upload / job intent
        |
        | accessZoneId / accessZoneIds
        | accessZoneCode / accessZoneCodes
        v
indexation_job (durable producer intent)
        |
        | normalize to exactly ONE effective selector
        v
claimed processing job
        |
        +--> acquisition M3
        +--> parser M4
        +--> OCR M5
        +--> normalization/split M6
        +--> prepared artifact/checkpoint/replay M7
        |
        | AccessZone lineage MUST remain attached to job/document context
        v
M8 AstraVector Delivery
        |
        | Start/Index:
        |   access_zone_id OR access_zone_code
        v
AstraVector Access Zone Registry
        |
        | resolves authoritative zone identity/policy
        v
DocumentRef.access_zone_id
        |
        v
persist resolvedAccessZoneId for status/delete/reconciliation
```

### 1.1 Non-negotiable rules

1. Producer compatibility may accept `accessZoneId`, `accessZoneIds[]`, `accessZoneCode`, `accessZoneCodes[]`.
2. One indexation job / one document version MUST normalize to exactly one effective AccessZone before downstream mutation.
3. Multiple distinct zones MUST be rejected; AstraIndexator MUST NOT silently fan out one job.
4. `accessZoneCode` is a four-character string matching `^[0-9]{4}$` and MUST preserve leading zeroes, including the complete `0000..0999` subrange.
5. AccessZone MUST survive crash/retry/replay. M7 replay MUST NOT require the producer to resubmit it and MUST NOT substitute a default zone.
6. M8 MUST forward the original normalized requested selector unchanged in meaning.
7. AstraVector remains authoritative for code → registry UUID resolution and policy.
8. Once AstraVector returns/resolves `DocumentRef.access_zone_id`, AstraIndexator MUST persist that resolved ID for status, delete and reconciliation.
9. Requested selector and resolved identity are distinct audit fields:
   - `requestedAccessZoneId`
   - `requestedAccessZoneCode`
   - `resolvedAccessZoneId`
10. Access level and AccessZone are independent dimensions.

## 2. TTL lineage

TTL intent is also producer-owned input and travels with the same durable job context.

For session ingestion:

```text
ttl_days = 0  -> inherit resolved AccessZone/platform policy
ttl_days > 0  -> explicit finite relative TTL in days
```

AstraIndexator MUST NOT derive TTL from AccessZone code and MUST NOT interpret `0` as unconditional forever. In particular, codes `0000..0999` remain valid and `ttl_days=0` is forwarded as inheritance without client-side coercion.

M8 MUST not conflate session `ttl_days` with the separate single-call `TtlPolicy` contract.

Generated protobuf DTOs are transport-only. They MUST NOT become AstraIndexator domain entities.

## 4. Canonical M7 → M8 boundary

M8 consumes the canonical prepared/replay result produced by M7. It MUST NOT re-run M4/M5/M6 to reconstruct transport input.

Required conceptual input:

```text
PreparedDeliveryDocument {
  jobId
  documentId
  documentVersion
  source identity/provenance
  contentHash
  requestedAccessZoneId?
  requestedAccessZoneCode?
  requestedTtlMode
  requestedTtlDays?
  metadata
  logicalFragments / canonical prepared parts
  compatibilityFingerprint
  manifestSha256
}
```

M8 maps canonical fragments/elements to AstraVector `LogicalBlock[]` through one anti-corruption mapper and structural validator.

M8 MUST NOT create AstraVector internal `PARENT`, `SUB_180`, `SUB_260`, embeddings, tokenizer chunks or Qdrant points.

## 5. Identity and idempotency freeze

Identities remain distinct:

```text
documentId != documentVersion != jobId != attemptId
           != fragmentId != ingestionSessionId != AstraVector chunkId
```

Recommended stable Start idempotency key:

```text
astraindexator:{documentId}:{documentVersion}:{contentHash}
```

Retries of the same logical Start MUST reuse the same key.

Append replay identity:

```text
same sessionId + same batchIndex + same batchContentHash -> safe replay
same sessionId + same batchIndex + different hash         -> integrity conflict
```

Finalize timeout is ambiguous and MUST be reconciled using downstream status before creating a new session/version.

---

## 6. Version/range guards

AstraIndexator domain may use a positive signed 64-bit `documentVersion`, but current session Start wire uses `uint32`.

Required Start guard:

```text
1 <= documentVersion <= 4_294_967_295
```

All current unsigned protobuf mappings MUST use explicit bounds checks; no unchecked truncation/wrap is permitted. This includes block order indexes, batch index, page/source numeric fields, totals and TTL days where represented as `uint32`.

---

## 7. Completion semantics

A completed ingestion session is not proof that knowledge is searchable.

M8 lifecycle evidence:

```text
SESSION_ACCEPTED
BLOCKS_STAGED
FINALIZED
VECTOR_READY
SEARCHABLE
FAILED
```

Normal AstraIndexator job completion requires downstream proof:

```text
GetDocumentVectorStatus(...).searchable == true
```

The resolved `DocumentRef` and downstream vector/sync status evidence MUST be persisted/recoverable for later M9 reconciliation.

## 10. M8.0 acceptance decision

The contract is frozen with the following architectural decision:

> **AccessZone is assigned at upload/job creation, persisted as durable producer intent, propagated through the entire AstraIndexator pipeline and replay path, normalized to exactly one effective zone, forwarded by M8 to AstraVector, and then reconciled with AstraVector's resolved `access_zone_id`. It is never inferred from document content and never silently replaced by an AstraIndexator default.**

Implementation may proceed to **M8.1 AccessZone/TTL durable lineage** only after this invariant is treated as a release-blocking contract requirement.
