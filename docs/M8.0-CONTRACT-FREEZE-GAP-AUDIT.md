## 1. Architectural invariant: AccessZone is producer intent and end-to-end lineage

> Historical section: UUID producer-selector wording below is superseded by the code-only notice above.

AccessZone is assigned at file/job submission by the trusted Spring Boot/business boundary. It is not discovered by OCR, parsing, splitting, M7 replay, or the M8 transport adapter.

Required lineage (historical representation):

```text
Spring Boot upload / job intent
        |
        | accessZoneId / accessZoneIds        # superseded
        | accessZoneCode / accessZoneCodes    # current producer selector
        v
indexation_job (durable producer intent)
        |
        | normalize to exactly ONE effective selector
        v
claimed processing job
        |
        +--> acquisition M3
        +--> parser M4
        +--> OCR M5
        +--> normalization/split M6
        +--> prepared artifact/checkpoint/replay M7
        |
        | AccessZone lineage MUST remain attached to job/document context
        v
M8 AstraVector Delivery
        |
        | Start: access_zone_code; access_zone_id=None
        v
AstraVector Access Zone Registry
        |
        | resolves authoritative internal UUID/policy
        v
DocumentRef.access_zone_id
        |
        v
private delivery_checkpoint.resolved_access_zone_id
```

### 1.1 Current non-negotiable rules

1. Producer boundary accepts `accessZoneCode` / `accessZoneCodes[]` only; producer UUID selectors are rejected.
2. One indexation job / one document version MUST normalize to exactly one effective AccessZoneCode before downstream mutation.
3. Multiple distinct codes MUST be rejected; AstraIndexator MUST NOT silently fan out one job.
4. `accessZoneCode` is a four-character string matching `^[0-9]{4}$` and MUST preserve leading zeroes.
5. AccessZoneCode MUST survive crash/retry/replay. M7 replay MUST NOT require the producer to resubmit it and MUST NOT substitute a default zone.
6. M8 MUST forward the original normalized code unchanged in meaning and send the compatibility UUID field as absent/None on Start.
7. AstraVector remains authoritative for code → internal UUID resolution and policy.
8. Once AstraVector returns `DocumentRef.access_zone_id`, AstraIndexator MAY persist it only as private downstream recovery/status evidence in `delivery_checkpoint.resolved_access_zone_id`.
9. Resolved UUID MUST NOT become producer/domain/inventory identity.
10. Access level and AccessZone remain independent dimensions.

## 2. TTL lineage

TTL intent is producer-owned input and travels with the same durable job context.

For session ingestion:

```text
ttl_days = 0  -> inherit resolved AccessZone/platform policy
ttl_days > 0  -> explicit finite relative TTL in days
```

AstraIndexator MUST NOT derive TTL from AccessZone code and MUST NOT interpret `0` as unconditional forever.

Current conceptual input:

## 5. Identity and idempotency freeze

Identities remain distinct:

```text
documentId != documentVersion != jobId != attemptId
           != fragmentId != ingestionSessionId != AstraVector chunkId
```

Current required stable Start idempotency identity:

```text
astra-indexator:{documentId}:{documentVersion}:{verifiedSourceContentHash}
```

Retries of the same logical Start MUST reuse the same key. Local `jobId` MUST NOT participate.

Append replay identity:

```text
same sessionId + same batchIndex + same batchContentHash -> safe replay
same sessionId + same batchIndex + different hash         -> integrity conflict
```

Finalize timeout is ambiguous and MUST be reconciled using downstream public status before creating a new session/version.

## 6. Version/range guards

AstraIndexator domain may use a positive signed 64-bit `documentVersion`, but current session Start wire uses `uint32`.

Required Start guard:

```text
1 <= documentVersion <= 4_294_967_295
```

All unsigned protobuf mappings MUST use explicit bounds checks; no unchecked truncation/wrap is permitted.

## 7. Completion semantics

A completed ingestion session is not proof that knowledge is searchable.

M8 lifecycle evidence:

```text
SESSION_ACCEPTED
BLOCKS_STAGED
FINALIZED
VECTOR_READY
SEARCHABLE
FAILED
```

Normal AstraIndexator job completion requires downstream proof:

```text
GetDocumentVectorStatus(...).searchable == true
```

The resolved `DocumentRef` and downstream vector/sync status evidence MUST be persisted/recoverable for later lifecycle reconciliation.

## 8. Historical gap audit

The original checklist below has been superseded as an operational status source by `IMPLEMENTATION-ROADMAP-2.0.md` and `M8-COMPLETION-REMEDIATION-SPEC.md`. It remains useful as historical traceability only.

### P0 historical requirements

- Generated protobuf client pinned to explicit llm2 contract revision.
- Dedicated AstraVector anti-corruption adapter; no hand-maintained parallel wire DTO contract.
- Durable job persistence for AccessZoneCode/TTL lineage.
- M7 checkpoint/replay preserves AccessZoneCode + TTL.
- Exactly-one-zone normalization before AstraVector mutation.
- Leading-zero AccessZoneCode tests.

- Stable Start idempotency and durable session checkpoint.
- Append batch index/hash checkpoint supports crash-safe replay.
- Finalize ambiguous-outcome reconciliation.
- Resolved downstream `DocumentRef.access_zone_id` private checkpoint evidence.
- Job cannot become COMPLETED until `searchable=true`.

### P1 historical hardening

- Explicit protobuf unsigned range guards.
- UNKNOWN-safe mapping for additive downstream states/enums.
- SourceLocation zero/unknown convention tests.
- SourceLink mapping with credential/token exclusion.
- Bounded batch sizing by block count and serialized bytes.
- Deadlines and bounded retry/backoff classified by gRPC status.
- Metrics/logging correlation without credentials.
- Compatibility fingerprint records M7 artifact revision + M8 wire contract revision.
- Contract/golden tests lock canonical hashes.

### P2 historical qualification evidence

- Real AstraVector integration: Start → Append(s) → Finalize → searchable.
- Crash matrix around Start/Append/Finalize/local commit.
- AstraVector unavailable/restart recovery.
- Duplicate/replayed delivery proves no duplicate logical document version.
- AccessZoneCode, including leading-zero code, integration evidence.
- Producer UUID rejection evidence.
- TTL inherit and finite-TTL integration evidence.
- Large-document bounded memory/RPC size.
- Post-implementation traceability audit against relevant TZ contracts.
