## 2. Public large-document ingestion path

The current public service is:

```proto
service AstraVectorIngestionFacade {
  rpc IndexLogicalDocument(...);
  rpc StartLogicalDocumentIngestion(...);
  rpc AppendLogicalDocumentBlocks(...);
  rpc FinalizeLogicalDocumentIngestion(...);
  rpc AbortLogicalDocumentIngestion(...);
  rpc GetLogicalDocumentIngestionStatus(...);
  rpc GetDocumentVectorStatus(...);
  rpc DeleteDocumentVectorsFacade(...);
}
```

M8 delivery uses the session path:

```text
StartLogicalDocumentIngestion
        ↓
AppendLogicalDocumentBlocks [0..N]
        ↓
FinalizeLogicalDocumentIngestion
        ↓
GetDocumentVectorStatus
```

Recovery/reconciliation additionally uses:

```text
GetLogicalDocumentIngestionStatus
AbortLogicalDocumentIngestion
```

`IndexLogicalDocument` is a separate one-shot facade and is not the durable M8 session protocol.

Current response:


### Access Zone rule

AstraVector accepts `access_zone_code` directly. AstraIndexator must preserve the producer code as a string and must not resolve it by reading AstraVector-owned PostgreSQL tables.

For AstraIndexator 1.0 the frozen producer contract remains:

```text
accessZoneCode: ^[0-9]{4}$
example: "0001" remains "0001"
```

`requested_access_zone_code` is producer intent. A later `DocumentRef.access_zone_id` is downstream evidence and must be stored separately.

## 4. LogicalBlock contract

Wire block:

```text
LogicalBlock
  block_id
  parent_block_id
  block_type
  text
  order_index
  source_location
  source_links[]
  metadata
```

`SourceLocation` contains page/character ranges, section/heading data and table coordinates. `SourceLink` contains link type, URL, label, MIME type, auth requirement, expiry and attributes.

Generated protobuf types remain below the AstraIndexator anti-corruption boundary. Application/domain objects are mapped explicitly into the generated wire types.

## 5. Append contract and replay identity

Current request:

```text
AppendLogicalDocumentBlocksRequest
  ingestion_session_id: string
  blocks: repeated LogicalBlock
  batch_index: uint32
  is_last_batch: bool
  batch_content_hash: string
```

Current response:

```text
AppendLogicalDocumentBlocksResponse
  ingestion_session_id: string
  status: string
  accepted_blocks: uint32
  accepted_batch_index: uint32
  warnings[]
```

Batch identity is therefore:

```text
ingestion_session_id + batch_index + batch_content_hash
```

The current M8 implementation intentionally persists prepared/accepted delivery batches so the same batch index/hash can be replayed after ambiguity or restart.

## 6. Canonical batch hash

Verified server behavior:

```text
LogicalBlock[]
→ canonical logical_block_to_json projection
→ JSON array preserving block order
→ serde_json::to_vec
→ SHA-256
→ lowercase hex
```

Map keys require deterministic lexical ordering on the Python side because upstream uses `serde_json = "1"` without `preserve_order`.

Important invariants:

```text
block array order is significant
batch_content_hash covers exactly one Append batch
source_location becomes {} when absent in canonical projection
Unicode is hashed as UTF-8 bytes
```

The AstraIndexator golden-vector fixture remains:

```text
tests/fixtures/astravector/canonical-hash-v1.json
```

## 7. Finalize contract and final content hash

Current request:

```text
FinalizeLogicalDocumentIngestionRequest
  ingestion_session_id: string
  final_content_hash: string
```

The response is `IndexLogicalDocumentResponse`, therefore a successful non-ambiguous Finalize can return:

```text
DocumentRef
OperationStatus
IndexingSummary
```

The final hash is intentionally different from the batch hash. AstraVector reconstructs staged blocks in batch/block order and hashes rendered text:

```text
optional heading.trim() + "\n"
block.text.trim() + "\n\n"
```

across all staged blocks, then SHA-256 lowercase hex.

Do not derive `final_content_hash` from concatenated batch hashes.

## 9. Known public-wire recovery gap

The current `GetLogicalDocumentIngestionStatusResponse` does **not** return `DocumentRef`.

Therefore this case remains ambiguous at the public wire boundary:

```text
Finalize request sent
→ transport outcome ambiguous
→ later ingestion status == COMPLETED
→ local caller has code-only AccessZone intent
→ GetDocumentVectorStatus requires DocumentRef.access_zone_id
```

This is a recovery identity gap in the current AstraVector public status API. It must not be “fixed” in AstraIndexator by:

```text
reading astravector.* tables
resolving accessZoneCode → UUID locally
inventing a new document version
starting a replacement ingestion session implicitly
```

The existing M8 implementation correctly records this as an explicit reconciliation/contract-gap condition.
