## Scope

M8.2.4 qualifies only two boundary concerns:

1. classification of one AstraVector ingestion gRPC failure into a recovery disposition;
2. validation of Start/Append response identity and Append acknowledgement invariants.

The classifier does not sleep, retry, reconcile, persist checkpoints, acquire leases, or resume work. Those execution mechanisms belong to later durable-delivery work.

## Pinned upstream authority

The policy is reviewed against the pinned AstraVector ingestion implementation:

```text
repository: alimbetov/llm2
server:     src/grpc/mod.rs
blob:       07afff94c4f3825ec953df55cd407ed7c653151a
proto blob: ed1eab5f56dfb73cc48927ad2effb759a2c4e01e
```

Verified upstream markers include:

```text
FAILED_PRECONDITION BATCH_HASH_MISMATCH
FAILED_PRECONDITION FINAL_CONTENT_HASH_MISMATCH
ABORTED             INGESTION_SESSION_FINALIZING
FAILED_PRECONDITION INGESTION_SESSION_{status}
NOT_FOUND           INGESTION_SESSION_NOT_FOUND
DATA_LOSS           INGESTION_COMPLETED_RESULT_MISSING
```

AstraVector also uses `RESOURCE_EXHAUSTED` for two semantically different cases.

Transient concurrency/capacity pressure:

```text
max_concurrent_ingestion_sessions exceeded
max_sessions_per_access_zone exceeded
max_sessions_per_document exceeded
```

Deterministic request/document limit violations:

```text
batch exceeds chunked_ingestion_max_blocks_per_batch
batch exceeds chunked_ingestion_max_batch_bytes
max_blocks_per_document exceeded
```

Therefore `RESOURCE_EXHAUSTED` cannot safely be classified from the gRPC code alone.

## Qualified decision table

| gRPC code / marker | Decision | Rationale |
| --- | --- | --- |
| `UNAVAILABLE` | `BACKOFF_AND_RETRY` | transport/storage availability; Start idempotency and Append same-index/same-hash make later execution safe |
| `DEADLINE_EXCEEDED` | `RECONCILE_STATUS` | outcome is ambiguous |
| `ABORTED` | `RECONCILE_STATUS` | server state may have changed concurrently |
| `RESOURCE_EXHAUSTED` + qualified concurrency marker | `BACKOFF_AND_RETRY` | capacity can clear without changing the request |
| other `RESOURCE_EXHAUSTED` | `PERMANENT_FAILURE` | fail-closed; request may require rebatching or producer correction |
| `FAILED_PRECONDITION` + hash mismatch | `PERMANENT_FAILURE` | resending unchanged content cannot repair the mismatch |
| `FAILED_PRECONDITION` + `FINALIZING`/`COMPLETED`/`ABORTED` | `RECONCILE_STATUS` | authoritative session state must be read |
| other `FAILED_PRECONDITION` | `PERMANENT_FAILURE` | fail-closed until explicitly qualified |
| `INVALID_ARGUMENT`, `OUT_OF_RANGE`, auth failures | `PERMANENT_FAILURE` | caller/contract defect |
| `NOT_FOUND` | `PERMANENT_FAILURE` | missing public identity is not repaired by blind status polling |
| `DATA_LOSS` | `PERMANENT_FAILURE` | integrity failure requires intervention |
| unknown code | `PERMANENT_FAILURE` | forward safety: no new retry semantics without contract review |

`classify_grpc_failure` is intentionally a pure classifier. `BACKOFF_AND_RETRY` and `RECONCILE_STATUS` are instructions to a later orchestration layer, not actions executed by M8.2.4.

## Response contract

M8.2.3 already proves real generated protobuf/gRPC Start and Append transport. M8.2.4 adds focused response-semantic checks.

### Start

The adapter rejects a malformed server `ingestion_session_id` as `INVALID_RESPONSE`.

### Append

A successful acknowledgement is accepted only if all of these match the request:

```text
response.ingestion_session_id == request.ingestion_session_id
response.accepted_batch_index  == request.batch_index
response.accepted_blocks       == len(request.blocks)
```

Malformed UUIDs and any identity/count/index mismatch are `INVALID_RESPONSE`; they are never silently accepted as delivered work.

## Fail-closed rule

Adding a new AstraVector gRPC code or error marker does not automatically make it retryable. The default is `PERMANENT_FAILURE` until the pinned upstream implementation and idempotency/recovery semantics are reviewed and this qualification evidence is updated.

This prevents an upstream contract change from silently introducing infinite retries or unsafe replay.

## Non-goals

M8.2.4 does not qualify:

- retry counters or backoff timing;
- durable DeliveryCheckpoint/DeliveryBatch state;
- crash/resume;
- fencing/leases;
- Finalize/Abort reconciliation execution;
- vector readiness reconciliation;
- parser/OCR replay behavior.

Those concerns must not be inferred from this qualification status.
