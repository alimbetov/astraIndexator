## 3. M8.2.1 batch hash authority

AstraVector `compute_batch_content_hash` performs:

```text
LogicalBlock[]
→ logical_block_to_json(block) for each block, preserving batch order
→ JSON array
→ serde_json::to_vec
→ SHA-256
→ lowercase hex
```

Canonical block projection contains exactly:

```text
block_id
parent_block_id
block_type
text
order_index
metadata
source_location
source_links
```

`source_location = {}` when the protobuf field is absent.

Each source link contains:

```text
type
url
label
mime_type
requires_auth
expires_at
attributes
```

The upstream `Cargo.toml` uses `serde_json = "1"` without the `preserve_order` feature. The
qualified Python projection therefore uses lexical map-key ordering, compact JSON separators,
direct UTF-8 (`ensure_ascii=False`) and SHA-256.

Important: **block array order is significant**. M8.2 must compute the hash over exactly the
blocks sent in that Append request.

The server recomputes the batch hash. Client/server mismatch is
`FAILED_PRECONDITION / BATCH_HASH_MISMATCH`. Replaying an existing `batch_index` is accepted only
when the recomputed server hash equals the stored hash.

## 4. M8.2.1 final hash authority

`final_content_hash` is intentionally **not** the hash of canonical batch JSON and is not a hash
over concatenated batch hashes.

AstraVector reconstructs staged blocks in:

```text
ORDER BY batch_index, block_index
```

and renders each block:

```text
if source_location.heading.strip() is non-empty:
    heading.strip() + "\n"

block.text.strip() + "\n\n"
```

The final rendered UTF-8 text is SHA-256 hashed and encoded as lowercase hex.

Therefore:

```text
batch_content_hash = SHA256(canonical JSON bytes of one Append batch)

final_content_hash = SHA256(rendered text bytes of all staged blocks)
```

These algorithms are deliberately separate.

A final mismatch produces `FINAL_CONTENT_HASH_MISMATCH`; current AstraVector records the error and
returns the session to a retryable ACTIVE state rather than accepting ambiguous content.

## 5. Golden fixture

Shared Python-side qualification fixture:

```text

```

It contains:

- pinned upstream blob identities;
- Cyrillic + Kazakh Unicode text;
- metadata inserted in non-lexical order;
- source-link attributes inserted in non-lexical order;
- source location + heading;
- an absent source location case;
- expected batch hash `ef37abcec55a701bdeb497347b336c484d715f2f099eb6213e3ca67a135b97d2`;
- expected final rendered text;
- expected final hash `33908c7ca960bc9c98ce3e1fd97b5e12fde3a9185b21ece53b1026a92fd43f52`.

The fixture is an AstraIndexator copy of verified Rust behavior. The long-term stronger gate is to
consume the same fixture from both repositories or publish it as a versioned contract artifact.
Until that is wired into llm2 CI, changing an expected digest in AstraIndexator without re-running
the Rust side is forbidden.

## 8. Change control

Any upstream change to one of these invalidates M8.2.1 qualification until reviewed:

```text
LogicalBlock / SourceLocation / SourceLink proto fields
logical_block_to_json
compute_batch_content_hash
render_logical_blocks_for_chunking
normalized_content_hash / hash_text
serde_json ordering/features
Append or Finalize mismatch/replay semantics
```

Do not silently adapt the Python digest to a new server behavior. Update the contract pin, golden
vectors and evidence in one reviewed change.
