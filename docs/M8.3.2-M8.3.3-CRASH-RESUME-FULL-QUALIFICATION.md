## M8.3.2 — Crash / Resume from M7 prepared artifacts

A reclaimed worker resumes delivery only through the durable M7 checkpoint and verified replay contract:

```text
expired worker A
  -> worker B claims new lease generation
  -> fence current owner in PostgreSQL
  -> load prepared_artifact_checkpoint
  -> verify immutable AccessZone / TTL / source-hash lineage
  -> PreparedArtifactReplayService.replay(...)
  -> verify manifest / checkpoint / compatibility
  -> PreparedArtifactDeliveryInputFactory
  -> qualified M8.2 LogicalBlock[] input
  -> continue durable AstraVector delivery
```

`DurablePreparedArtifactResumeService` does not import or invoke acquisition, parser, OCR, normalizer or splitter execution services. An absent or incompatible M7 artifact produces `PreparedArtifactReprocessRequired`; it does not silently fabricate or partially reuse an artifact.

The immutable lineage check requires the checkpoint to match the durable job for:

```text
source_content_hash
requested_access_zone_id
requested_access_zone_code
requested_ttl_days
```

The producer selector remains unchanged during worker reclaim.

Focused PostgreSQL qualification:

```text
tests/test_m8_3_2_prepared_artifact_crash_resume.py
```

It proves a new lease generation can rebuild the M8.2 delivery input from the M7 artifact, while an AccessZone/TTL lineage mismatch fails closed before replay.

## M8.3 completion invariants

M8.3 is qualified only if the complete branch head proves all of the following:

1. every authoritative delivery mutation is lease-generation fenced;
2. mutating RPCs require a safe lease window;
3. PREPARED precedes Append and ACCEPTED follows only a fenced acknowledgement commit;
4. retries use PostgreSQL time, bounded exponential backoff and attempt budgets;
5. deterministic/permanent failures do not enter blind retry loops;
6. ambiguous downstream outcomes enter reconciliation rather than normal retry;
7. poison jobs become DEAD_LETTER after budget exhaustion;
8. a reclaimed worker reuses a compatible M7 artifact without parser/OCR rerun;
9. AccessZone/TTL/source identity survives retry and reclaim unchanged;
10. the same AstraVector document version/idempotency identity is preserved across recovery;
11. full pytest + PostgreSQL integration, Ruff, scoped mypy and package build all pass on one final head.

## Boundary with M8.4

M8.3 qualifies crash-safe execution and immediate operation-specific reconciliation needed to make a mutating retry safe. It does not own long-running local-vs-AstraVector convergence loops, historical repair, or periodic SEARCHABLE reconciliation. Those remain M8.4.
