## Purpose

M8.3.1 turns the retry fields already present in `IndexationJob` and `JobCoordinator.schedule_retry()` into a bounded stage-aware failure policy. PostgreSQL remains the only durable scheduling authority.

The target contract is:

```text
failure
  -> classify
  -> retry / reconcile / fail / dead-letter / abandon
```

No automatic path may reset document identity, AccessZone/TTL intent, ingestion identity, batch hash or idempotency key.

## Canonical failure classes

The implementation follows TZ-13:

```text
TRANSIENT
PERMANENT_INPUT
PERMANENT_POLICY
RESOURCE_LIMIT
DOWNSTREAM_AMBIGUOUS
OWNERSHIP_LOST
CANCELLED
INTERNAL_BUG
DEPENDENCY_UNAVAILABLE
```

## Actions

```text
TRANSIENT / DEPENDENCY_UNAVAILABLE
  if attempt_count < max_attempts
      -> RETRY_WAIT
  else
      -> DEAD_LETTER

PERMANENT_INPUT / PERMANENT_POLICY / RESOURCE_LIMIT
      -> FAILED

DOWNSTREAM_AMBIGUOUS
      -> RECONCILE
      -> no blind retry mutation

OWNERSHIP_LOST
      -> ABANDON
      -> stale worker performs no durable retry/failure transition
```

`INTERNAL_BUG` is fail-closed by default. It is not automatically retried until a specific bug class is proven replay-safe.

## Backoff

Baseline defaults follow TZ-13:

```text
base delay = 5s
max delay = 15m
jitter = 20%
```

The delay is exponential and bounded. Jitter is deterministic from `(job_id, lease_generation, attempt_count)` so repeated evaluation of the same attempt gives the same schedule decision.

The policy computes only a delay. `JobCoordinator.schedule_retry()` persists:

```text
next_retry_at = PostgreSQL now() + delay
```

Therefore worker host clocks do not become scheduling authority.

## Poison-job semantics

When a retryable failure reaches the durable attempt budget:

```text
PROCESSING
   -> DEAD_LETTER
```

The transition preserves:

- job/document identity;
- source reference already on `IndexationJob`;
- processing stage;
- attempt count and max attempts;
- last error code/message;
- lease generation and worker evidence in `ProcessingAttempt` / `JobEvent`;
- M7 prepared artifact and M8 delivery checkpoints, which are not deleted by this transition.

`JOB_DEAD_LETTERED` audit evidence includes failure class, attempt count, max attempts and error code.

Permanent deterministic failures move to `FAILED`, not `DEAD_LETTER`, because repeated execution is not expected to heal them.

## AstraVector transport classification

`DurableFailureHandler.classify_exception()` reuses the qualified M8.2 transport classifier:

- `BACKOFF_AND_RETRY` -> `DEPENDENCY_UNAVAILABLE`;
- `RECONCILE_STATUS` -> `DOWNSTREAM_AMBIGUOUS`;
- fail-closed transport errors -> `PERMANENT_POLICY` until a more specific domain mapping exists.

This keeps M8.3 retry execution consistent with M8.2 wire semantics.

## Qualification tests

`tests/test_m8_3_1_retry_backoff_dead_letter.py` proves:

1. retryable failure -> `RETRY_WAIT` with PostgreSQL `next_retry_at`;
2. current attempt is closed as `RETRY_WAIT`;
3. exhausted retryable job -> `DEAD_LETTER`;
4. permanent input failure -> immediate `FAILED`;
5. ambiguous downstream outcome -> `RECONCILE` without retry-state mutation;
6. ownership loss -> `ABANDON` without stale-worker mutation;
7. exponential+jitter delay is deterministic and bounded.

## Boundary

M8.3.1 does not implement M8.3.2 prepared-artifact crash/resume or M8.4 long-running reconciliation. It only classifies and persists retry/terminal decisions at a currently-owned failure boundary.
