# M4.1 / M4.2 — Extended Document Parsers

## Status

Implementation baseline complete in PR #16; merge is gated by AstraIndexator CI.

## Scope

M4.1:

```text
XLSX
PPTX
CSV
HTML
```

M4.2:

```text
ODT
RTF
EPUB
```

All formats reuse the canonical M4 model:

```text
AcquiredSource
→ exact detectedFormat handler
→ ParsedDocument
→ DocumentElement[]
→ OcrCandidate[] where applicable
```

No format introduces an independent chunking, embedding or vector path.

## Admission boundary

M3 safe admission is extended before parser routing:

- OOXML/ZIP packages are identified by required internal package members, not extension alone;
- XLSX requires `xl/workbook.xml`;
- PPTX requires `ppt/presentation.xml`;
- ODT requires the ODF mimetype plus `content.xml`;
- EPUB requires `application/epub+zip` plus `META-INF/container.xml`;
- generic ZIP remains unsupported;
- nested containers remain disabled under the M3.1 default policy;
- RTF requires a real RTF signature and bounded group nesting;
- HTML requires markup evidence;
- CSV requires stable delimiter/field-count evidence; ambiguous delimited text remains TXT.

## Handler semantics

### XLSX

- `openpyxl` read-only adapters;
- sheet/row/cell/range provenance;
- formulas are never executed;
- formula expression is evidence metadata;
- cached/displayed value is preferred for retrieval text when available;
- sparse rows are emitted only when populated;
- sheets/rows/columns/non-empty cells/cell text are bounded.

### PPTX

- slide/shape provenance;
- title identified by stable shape identity;
- title emitted as `HEADING`;
- tables remain structured metadata;
- pictures become first-class `IMAGE` + OCR candidates;
- speaker notes remain a separate scope;
- deterministic title-first then spatial order.

### CSV

- streaming `csv.reader`;
- detected delimiter and quote character retained;
- row/column provenance;
- header association preserved in both structured metadata and retrieval representation;
- whole file is never loaded into an arbitrary table string.

### HTML

- offline BeautifulSoup/lxml parsing;
- scripts/styles/noscript/template removed from retrieval content;
- no JavaScript execution;
- no link/iframe/image fetching;
- DOM path and element ID provenance;
- remote image references are recorded as `IMAGE` metadata only.

### ODT

- ODF logical headings/paragraphs/lists/tables;
- logical node provenance;
- no fabricated physical page numbers.

### RTF

- bounded RTF admission;
- `striprtf` text conversion;
- paragraph boundaries retained;
- `RTF_STRUCTURE_PARTIAL` warning explicitly states baseline structure limitations.

### EPUB

- EPUB package admission;
- content follows spine order;
- navigation document is excluded from retrieval body;
- chapter/section HTML structure is mapped to canonical elements;
- `spineIndex`, `href` and DOM path are retained.

## Resource limits

`ParseLimits` now additionally bounds:

```text
max_sheets
max_rows
max_columns
max_non_empty_cells
max_cell_chars
max_slides
max_shapes
max_dom_nodes
max_epub_spine_items
```

M3.1 source/container/workspace limits remain authoritative upstream.

## Evidence

`tests/test_m4_extended_parsers.py` covers:

- XLSX admission and sheet/cell/formula provenance;
- PPTX slide/shape/table/title semantics;
- CSV stable delimiter and header-associated rows;
- HTML offline parsing and script exclusion;
- RTF admission/conversion;
- ODT structure without fake pages;
- EPUB spine order and href provenance;
- ambiguous comma-delimited text not being promoted to CSV.

Existing M1–M4 tests run in the same CI job to detect regressions.

## Deferred improvements

The following are intentionally not claimed by this baseline:

- chart visual interpretation;
- spreadsheet formula calculation;
- browser rendering/CSS layout;
- RTF full style/table fidelity;
- OCR of referenced HTML/EPUB images without durable extracted-image artifacts;
- macro-enabled legacy Office formats.

These require explicit future scope and evidence rather than implicit parser behavior.
