## Scope

M8.2.3 qualifies the actual transport boundary for the first two large-document ingestion RPCs:

```text
StartLogicalDocumentIngestion
AppendLogicalDocumentBlocks
```

It does not qualify retry/backoff, durable delivery checkpoints, Finalize ambiguity recovery, Abort reconciliation, or vector-readiness reconciliation. Those remain later M8.2 steps.

## Upstream authority

AstraVector wire authority remains the pinned `alimbetov/llm2` protobuf contract:

```text
proto/astravector_embedding.proto
blob: ed1eab5f56dfb73cc48927ad2effb759a2c4e01e
```

`AstraVectorProtoMapper` produces generated protobuf messages and `AstraVectorGrpcAdapter` invokes the generated `AstraVectorIngestionFacadeStub`.

## Transport invariants

### Start

The adapter MUST:

1. map the application command through the pinned generated protobuf module;
2. call `StartLogicalDocumentIngestion` on the generated ingestion facade stub;
3. pass the configured per-RPC deadline;
4. pass configured gRPC metadata;
5. preserve `access_zone_code` byte-for-byte, including `"0001"`;
6. preserve `ttl_days=0` on the wire;
7. reject malformed server `ingestion_session_id` responses as `INVALID_RESPONSE`;
8. map unknown session status strings to the forward-compatible `UNKNOWN` application state;
9. translate `grpc.RpcError` to `AstraVectorGrpcError` without inventing retry policy.

### Append

The adapter MUST:

1. call `AppendLogicalDocumentBlocks` through the generated stub and real protobuf serialization;
2. preserve `ingestion_session_id`, `batch_index`, `is_last_batch`, and `batch_content_hash`;
3. serialize nested `LogicalBlock`, `SourceLocation`, `SourceLink`, metadata, and Unicode text through the real generated protobuf classes;
4. require server acknowledgement to match the same session id;
5. require acknowledged batch index to equal the request batch index;
6. require acknowledged block count to equal the number of sent blocks;
7. translate gRPC transport failures without making retry/reconciliation decisions in this layer.

## Qualification test

`tests/test_m8_2_3_real_grpc_start_append.py` starts an in-process gRPC server using the same generated AstraVector service definitions used by production client code.

The tested path is therefore:

```text
StartIngestionCommand / AppendBlocksCommand
        ↓
AstraVectorProtoMapper
        ↓
generated protobuf request
        ↓
generated AstraVectorIngestionFacadeStub
        ↓
real grpc.Channel
        ↓
real protobuf serialization/deserialization
        ↓
generated AstraVectorIngestionFacadeServicer
        ↓
generated protobuf response
        ↓
AstraVectorGrpcAdapter response validation
```

This is intentionally stronger than a Python fake-stub unit test. It proves compatibility between the pinned generated client, the mapper, the channel, and the generated service contract without requiring a live AstraVector model/runtime in CI.

The test proves:

- `access_zone_code="0001"` survives the full gRPC round trip;
- `ttl_days=0` survives the full gRPC round trip;
- configured metadata reaches the server context;
- a positive configured RPC deadline reaches the server context;
- nested block provenance survives protobuf transport;
- server `UNAVAILABLE` on Append becomes `AstraVectorGrpcError(code="UNAVAILABLE")`.

The server-side gRPC deadline value may differ from the configured client timeout by a few milliseconds because of gRPC deadline accounting. The qualification test therefore permits a narrow bounded jitter while still proving that a positive finite deadline is propagated.
