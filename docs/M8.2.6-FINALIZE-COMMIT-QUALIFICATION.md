## Qualified boundary

M8.2.6 covers the generated protobuf Finalize and ingestion-status wire contract, Finalize response identity validation, and the decision required after an ambiguous mutating Finalize result.

Pinned wire methods:

- `FinalizeLogicalDocumentIngestion` -> `IndexLogicalDocumentResponse`
- `GetLogicalDocumentIngestionStatus` -> `GetLogicalDocumentIngestionStatusResponse`

A direct Finalize acknowledgement is valid only when `document_id`, `document_version`, and any already-known resolved `access_zone_id` match the expected delivery identity.

## Ambiguous Finalize policy

Because Finalize mutates remote state, these failures reconcile the existing session before replay:

- `DEADLINE_EXCEEDED`
- `UNAVAILABLE`
- `ABORTED`
- `FAILED_PRECONDITION` only when M8.2.4 recognizes a pinned session-state marker such as `INGESTION_SESSION_FINALIZING` or `INGESTION_SESSION_COMPLETED`.

The policy remains fail-closed for `CANCELLED`, `UNKNOWN`, unknown precondition markers, and hash mismatch errors.

This fixes an earlier inconsistency where the Finalize runner treated `CANCELLED` and `UNKNOWN` as automatically ambiguous but did not reconcile qualified `FAILED_PRECONDITION` session-state markers.

## Reconciliation rule

- `ACTIVE`: exact same Finalize command may be retried.
- `FINALIZING`: poll only; do not send another Finalize.
- `COMPLETED`: no second Finalize; continue only with available downstream document identity.
- `FAILED`, `ABORTED`, `EXPIRED`: terminal.
- unknown state: fail closed / reconciliation pending.

The current public ingestion-status response does not contain `DocumentRef`. If a Finalize response is lost, status later reports `COMPLETED`, and resolved `access_zone_id` is unavailable locally, AstraIndexator must not synthesize a UUID from `accessZoneCode`; it raises `FinalizeReadinessIdentityUnavailable`.
