## 8. Contract pin / compatibility-fingerprint finding

M7 `ArtifactCompatibility` records parser/OCR/normalizer/splitter identity and configuration, but it does not currently include the selected M8 wire-contract revision. The generated AstraVector client is independently pinned and tested, so runtime delivery is protected against silent proto drift; however M8.0 P1 asks for a compatibility fingerprint linking M7 artifact revision and M8 wire revision.

Decision:

**GAP-E05 (traceability metadata, non-wire):** add an M8 delivery compatibility fingerprint/checkpoint field or equivalent immutable evidence that records at least:

```text
prepared artifact compatibility_sha256
M8 wire contract revision/proto blob
canonical hash revision
batching contract revision/config relevant to replay
```

This is required before M8.G final qualification because it improves forensic/replay compatibility. It must not alter M7 artifact content solely to inject a transport concern; preferred ownership is M8 delivery checkpoint/evidence.

## 11. M8.E closure backlog

M8.E SHALL be limited to the audit-confirmed closure list. No unrelated feature branches are permitted.

### GAP-E01 — LogicalBlock structural validation

Add one reusable validation boundary before batching/protobuf mapping that proves:

- exactly one root `DOCUMENT`;
- unique IDs;
- all non-root parents exist;
- no cycles/self-parenting;
- deterministic/unique order indexes;
- valid root parent semantics;
- supported structural relationships as far as TZ-11 currently defines them.

Add focused tests for valid tree, duplicate ID, missing parent, self-parent and multi-node cycle.

### GAP-E02 — SourceLink secret exclusion

Add fail-closed SourceLink validation for URLs/attributes containing credential-bearing material. At minimum reject/sanitize according to an explicit allow/deny contract for:

- userinfo credentials in URLs;
- bearer/access tokens;
- API keys/secrets/passwords in attributes/query fields;
- authorization headers represented as metadata.

Do not log the rejected secret value.

### GAP-E03 — production failure-policy wiring

Wire `DurableFailureHandler` at the actual owned job execution boundary so Start/Append/Finalize/readiness exceptions drive the qualified actions:

```text
RETRY_WAIT
RECONCILE
FAILED
DEAD_LETTER
ABANDON
```

The wiring must preserve the existing operation-specific ambiguity rules and must never let a stale worker perform the terminal/retry mutation.

### GAP-E04 — ambiguous Finalize DocumentRef recovery

This is primarily an AstraVector public-contract gap. Preferred closure order:

1. extend/confirm public session-status/finalize status API to return authoritative `DocumentRef`; or
2. provide a public authoritative lookup/resolution operation suitable for this recovery case.

AstraIndexator MUST NOT reproduce AstraVector code→UUID derivation as a workaround.

If upstream cannot be changed in the M8 window, this gap remains a release blocker for code-only ingestion under ambiguous Finalize.

### GAP-E05 — delivery compatibility fingerprint

Persist immutable delivery-contract evidence linking the verified M7 artifact to the selected M8 wire/hash/batching contract revision.
