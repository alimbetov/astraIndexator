# M6.1 — RAG & Correctness Hardening

## Status

M6 post-implementation hardening after RAG/code review. This document supplements TZ-07, TZ-08, `M6-PREIMPLEMENTATION-REVIEW.md`, and `M6-NORMALIZATION-LOGICAL-SPLITTER.md`.

## Closed correctness gaps

### Processing identity chain

`TextNormalizationService.normalize()` accepts `upstream_processing_fingerprint`. The normalized processing fingerprint now hashes:

- upstream M5/OCR processing fingerprint when supplied;
- source SHA-256;
- parser identity;
- normalizer profile id/version;
- canonical hash of every semantic normalization-profile field.

`LogicalFragment` identity additionally includes `NormalizedDocument.processing_fingerprint` and a canonical hash of every semantic splitter-profile field. Therefore model/profile/limit configuration changes cannot silently reuse the same M6 identity merely because a human forgot to bump a version string.

### Multiline normalization

Line joining is no longer unconditional.

- parser-classified ordinary `PARAGRAPH` is treated as parser structural-continuity evidence, preserving the established parser contract;
- explicit `lineWrapEvidence` permits line joining;
- `lineWrapHyphenEvidence` permits conservative dehyphenation and line joining;
- `OCR_TEXT` is excluded from implicit paragraph joining and remains multiline unless explicit wrap evidence exists;
- `preserveLineBreaks` overrides ordinary paragraph continuity;
- code/preformatted layout remains unchanged.

Protected-token recognition covers URL, email, IPv4, UUID, semantic version, long digest, four-digit codes including leading-zero access-zone values, and dotted technical identifiers before risky dehyphenation.

### Hard fragmentation guards

`hard_max_chars`, `hard_max_words`, and `hard_max_sentences` are now postconditions, not advisory targets.

Every emitted fragment is checked after materialization. Oversized sentences/text are force-split under character and word guards. A single oversized table row receives a marked forced fallback instead of escaping the hard limit.

### Small-fragment policy

`min_chars` now participates in deterministic consolidation. Compatible small groups merge when this does not cross an incompatible structure or violate a hard guard.

Explicit small-fragment exceptions are preserved independently for roles such as:

- `FAQ`;
- `WARNING`;
- `LEGAL_DEFINITION` / `DEFINITION`;
- `NOTICE`;
- `ALERT`.

Tables and code blocks also remain structural small-fragment exceptions.

### Context flags

Runtime now honors:

- `repeat_heading_context`;
- `repeat_parent_headings`;
- `repeat_table_header`;
- `repeat_list_intro`.

Synthetic context remains outside physical source provenance.

### Table provenance

`FragmentSource` now includes:

- `table_row_from`;
- `table_row_to`.

Oversized table continuations therefore identify the actual contributing row range instead of pointing only to the whole table element.

### Sentence-boundary v2

RU/KK/EN/mixed profiles now distinguish always-nonterminal prefix/title abbreviations from terminal-capable abbreviations.

Examples:

- `Dr. Smith` remains one sentence prefix;
- `г. Алматы` remains one sentence prefix;
- `... и др. Далее ...` may end at `др.` because uppercase look-ahead indicates a new sentence;
- `... etc. Next ...` may end at `etc.`;
- internal version/IP/URL/email dots remain protected.

## Verification

M6.1 adds regression coverage for:

- upstream fingerprint changes;
- semantic profile config changes without version bumps;
- OCR multiline preservation;
- explicit wrap joining;
- hard word limit;
- hard sentence limit;
- oversized table-row fallback;
- table row-range provenance;
- `min_chars` consolidation;
- explicit small-fragment exceptions;
- context profile flags;
- splitter config hash identity;
- terminal-capable abbreviations;
- always-nonterminal title/location prefixes;
- unknown-language fallback;
- invalid non-positive `documentVersion` rejection.

The full repository CI, including PostgreSQL/Testcontainers suites from earlier milestones, is the merge gate.

## Remaining non-blocking work

M6.1 does **not** claim final BGE-M3 calibration. TZ-17/TZ-11 still own:

- real BGE-M3 tokenizer distribution measurement;
- downstream truncation target verification;
- retrieval-quality comparison against naive splitting;
- corpus calibration for sentence-boundary/profile revisions.

Strict end-to-end streaming materialization is also not claimed as complete. The splitter now consumes normalized elements through an iterator instead of first materializing a full `_Unit[]`, but the public `split()` contract still returns a tuple of fragments and normalization still returns an immutable normalized document. A future prepared-artifact/streaming boundary may expose iterator/sink APIs without changing M6 semantic rules.

## Decision

After this hardening and green full CI, M6 can be treated as **correctness-closed for the current implementation baseline**, with production retrieval/token calibration explicitly deferred to TZ-17/TZ-11.
