## Purpose

M8.2.8 qualifies the public AstraVector read-side contract used after Finalize. The core invariant is:

```text
IngestionSession COMPLETED != document SEARCHABLE
```

Finalize/session completion only proves that AstraVector accepted the logical document and entered its asynchronous vector lifecycle. AstraIndexator may claim retrieval readiness only from `GetDocumentVectorStatus` evidence.

## Pinned wire authority

The generated client remains pinned to AstraVector proto blob:

```text
ed1eab5f56dfb73cc48927ad2effb759a2c4e01e
```

The public facade exposes:

```text
GetDocumentVectorStatus(GetDocumentVectorStatusRequest)
  -> GetDocumentVectorStatusResponse
```

with exact `DocumentRef`, `OperationState`, `progress_percent`, `searchable`, `ready_to_activate`, and `GetVectorSyncStatusResponse` evidence.

## Readiness state machine

AstraIndexator interprets the public status as follows:

```text
ACCEPTED / INDEXING / VECTORING / PUBLISHING / SYNCING
    -> WAIT / FINALIZED

READY_TO_ACTIVATE + ready_to_activate=true + consistent sync evidence
    -> WAIT / VECTOR_READY by default
    -> READY_TO_ACTIVATE only when an explicit external/manual activation policy allows handoff

ACTIVE + searchable=true + consistent sync evidence
    -> SEARCHABLE

FAILED / EXPIRED / DELETED / DELETE_SCHEDULED / DELETING
    -> TERMINAL
```

Unknown operation states fail closed.

`READY_TO_ACTIVATE` is deliberately not equivalent to `SEARCHABLE`. M8.2 does not call the legacy/v004 activation control-plane RPC.

## Integrity requirements

A ready/searchable response is rejected when any of the following contradicts it:

- `synced_bindings != expected_bindings` when expected bindings are non-zero;
- pending or failed bindings remain;
- pending/retry/failed outbox work remains;
- Qdrant reports missing expected points;
- found Qdrant points are fewer than expected points;
- `ACTIVE` reports `searchable=false`;
- `READY_TO_ACTIVATE` reports `ready_to_activate=false` or `searchable=true`;
- a transitional or terminal state reports readiness flags;
- any sync counter is negative;
- progress is outside `0..100`;
- response `DocumentRef` differs from the requested access-zone/document/version identity.

The adapter therefore treats status evidence as an integrity contract, not as advisory telemetry.

## Boundary with later milestones

M8.2.8 qualifies only interpretation of one authoritative status observation. It does not add durable polling schedules, persisted reconciliation state, retry/backoff execution, crash/resume, leases/fencing, or retrieval probes.

Those concerns remain outside this step:

- durable delivery execution -> M8.3;
- local/remote state reconciliation and SEARCHABLE confirmation over time -> M8.4;
- real retrieval proof -> M8.5 release qualification.
