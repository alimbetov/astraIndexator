## Qualification objective

The final M8.2 boundary is:

```text
verified M7 PreparedArtifact
        ↓
PreparedArtifactDeliveryInputFactory
        ↓
PreparedArtifactDeliveryMapper
        ↓
AstraVectorDeliveryInput(LogicalBlock[])
        ↓
AstraVectorDeliveryCoordinator
        ↓
qualified M8.2 Start / Append / Finalize / status contracts
```

M8.2.9 proves that the coordinator can consume canonical M7 output without rerunning parser/OCR/splitter and without requiring callers to handcraft `LogicalBlock[]`.

## Audit finding 1 — missing M7 → M8.2 mapper

Before M8.2.9, M7 persisted canonical `LogicalFragment` records using `PreparedArtifactAssembler`, but `AstraVectorDeliveryCoordinator` accepted prebuilt `logical_blocks` directly. The required TZ-11 boundary:

```text
LogicalFragment[] -> LogicalBlockMapper -> LogicalBlock[]
```

therefore existed in specification but not in implementation.

M8.2.9 adds:

```text
src/astra_indexator/application/prepared_artifact_delivery.py
src/astra_indexator/application/prepared_artifact_wiring.py
```

The mapper is deliberately pure: no database access, retries, leases, checkpoints, remote calls, or recovery decisions.

### Mapping contract

A verified M7 artifact maps to:

- one deterministic synthetic structural `DOCUMENT` root;
- one child block per canonical M7 logical fragment in deterministic sequence order;
- `SECTION -> SECTION`;
- `PARAGRAPH -> PARAGRAPH`;
- `LIST -> LIST`;
- `TABLE -> TABLE`;
- `CODE -> CODE_BLOCK`;
- `OCR/OTHER -> PARAGRAPH` until a more specific public wire type exists;
- M7 `context_prefix` prepended to block text while also retained explicitly as metadata so synthetic context remains distinguishable from source-derived `normalized_text`;
- hierarchy mapped to `SourceLocation.section_path/heading`;
- available page provenance mapped without fabricating unavailable character/row/column coordinates;
- M7 fragment metadata converted deterministically to protobuf-compatible string metadata.

The mapper rejects empty artifacts, malformed fragment records, identity mismatches, duplicate `fragment_id`, duplicate sequence values, negative sequence/source values, unsupported fragment types, and blank normalized text.

## Audit finding 2 — prepared source hash was dropped

Before M8.2.9, coordinator Start used:

```text
content_hash = job.source_content_hash or ""
```

The M8.2 protobuf mapper requires a valid SHA-256 digest, while every verified M7 manifest already carries authoritative `identity.source_sha256`. A job without a separately populated source hash could therefore pass the fake-port coordinator test but fail at the real generated protobuf boundary.

M8.2.9 closes this gap:

```text
PreparedArtifact.manifest.identity.source_sha256
        ↓
AstraVectorDeliveryInput.source_content_hash
        ↓
StartIngestionCommand.content_hash
```

The coordinator still prefers explicit prepared-artifact evidence supplied in the delivery input and falls back to the durable job value for legacy callers.

## Identity assertion

`PreparedArtifactDeliveryInputFactory` requires:

```text
artifact.manifest.identity.document_id      == claimed/job document_id
artifact.manifest.identity.document_version == claimed/job document_version
```

A mismatch fails before transport. This prevents a valid artifact for another version from being delivered under the current job identity.

## AccessZone / TTL wiring audit

The coordinator continues to construct Start from the durable M8.1 producer intent:

```text
access_zone_id   = job.requested_access_zone_id
access_zone_code = job.requested_access_zone_code
ttl_days         = job.requested_ttl_days or 0
```

`accessZoneCode="0001"` therefore remains a four-character string. A downstream `resolved_access_zone_id` returned by AstraVector remains separate evidence and never replaces the producer selector.

## Coordinator completion boundary

The coordinator path remains:

```text
Start
 -> deterministic Append sequence
 -> Finalize
 -> GetDocumentVectorStatus/readiness
 -> JobCoordinator.complete
```

Production readiness requires the qualified M8.2.8 `SEARCHABLE` boundary. Session `COMPLETED` alone is not sufficient.

## M8.3/M8.4 boundary audit

The branch already contains durable delivery/reconciliation implementation and regression tests such as:

- `DeliveryCheckpoint` / `DeliveryBatch` persistence;
- bound-session reuse;
- PREPARED/ACCEPTED replay;
- crash/restart scenarios;
- Finalize ambiguity reconciliation;
- readiness polling/persistence.

These tests may continue to run and protect compatibility, but **they do not make those semantics owned or qualified by M8.2**.

Milestone ownership remains:

```text
M8.2  wire contract, mapper, transport, deterministic wire batching,
      Finalize/Abort/status interpretation, M7 -> wire coordinator handoff

M8.3  durable delivery: checkpoints, batches, idempotency execution,
      retry/backoff, fencing, crash/resume, no parser/OCR rerun

M8.4  local <-> AstraVector reconciliation, ambiguous commit recovery over time,
      SEARCHABLE confirmation and document/version/binding verification
```

This distinction is normative for subsequent qualification work.

## Real AstraVector deployment
